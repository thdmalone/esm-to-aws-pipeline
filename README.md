# Aperio ESM to AWS Pipeline

This repository utilizes data exported from Aperio eSlideManager to upload whole slide images (WSI) to an AWS S3 bucket.

## Install

### Dependencies

- Python >=3.12
- AWS CLI
  - Multiple profiles are supported per `~/.aws/config` file specification

### venv + pip

Navigate to a directory that will contain the clone of this repository, then execute the lines below in the terminal

```bash
git clone "https://github.com/thdmalone/esm-to-aws-pipeline"
cd esm-to-aws-pipeline
python -m venv venv
venv/Scripts/activate
pip install -e
```

## Overview

The pipeline consists of three steps that can be executed individually:

1. Create a processing manifest from the ESM export (`eta manifest`)
2. Copy images, group them, then compress and delete the copied versions (`eta compress`)
3. Upload the compressed groups to an S3 bucket (`eta upload`)

Alternatively, the pipeline can be executed with comprehensive command:

1. A complete run starting from the the ESM export (`eta run`)

\*Note: The manifest doesn't necessarily have to be generated by step 1, but it should have all required headers and data. This structure is validated if this option is chosen.

# General Usage

1. Start a new project -- the specified directory does not have to exist

```bash
eta new "path/to/project/directory"
```

This will create the following inside the project directory:

- `batches` : a folder to hold ESM export CSVs (unprocessed)
- `runs` : a folder for processed batches
- `config.yml` : a file for project configurationn

2. Export WSI data from eSlideManager with the following options selected, rename the exported CSV to the batch id, and place it into the `batches` directory:
   - Specimen Acc#
   - Image Id
   - File Location

3. Run pipeline via modular or comprehensive commands (_assuming `config.yml` contains optional arguments_)

- Modular:

```bash
eta manifest --p "path/to/project" --b "batch_id"
eta compress --p "path/to/project" --b "batch_id"
eta upload --p "path/to/project" --b "batch_id"

```

- Comprehensive:

```bash
eta run --p "path/to/project"
```

# ESM Best Practices

1. WSIs belonging to the same batch are saved to the same "Specimen" inside ESM. For example, all images associated with the batch R01-0001 are saved to a specimen labelled R01-0001. This will allow the batch ID to be inferred from the "Specimen Acc#" column, if desired.
2. ESM data is exported per batch (i.e., each export contains WSI data associated with only one batch). Exports containing multiple batches will be separated.
